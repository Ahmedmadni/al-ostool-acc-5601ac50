# ONEXA — المرحلة الثانية عشرة: تبعيات الترحيل المالي وترتيب Staging

**تاريخ الفحص:** 19 نوفمبر 2026  
**حالة الإنتاج:** HOLD — مراجعة المخطط وصلاحياته بالقراءة فقط، دون استعلام عن قيود العملاء أو تعديلها.

## ما كشفته القاعدة المستضافة فعليًا

أُجري فحص `onexa_b4_module_dependencies_READ_ONLY.sql` على الفهارس والتعريفات والدوال المثبتة فقط؛ وهو لا يقرأ قيم المبالغ أو مصادر المستندات. أظهرت النتائج أن:

| العقدة | ما تم التحقق منه | المانع الحالي |
|---|---|---|
| B4 | البنية الأساسية والأستاذ مثبتان | محرك الإنتاج لم يجتز بعد متطلبات المرحلة العاشرة (1/11 فقط) |
| G35/G36/G39 | دوال المبيعات والمشتريات وقبض العملاء مثبتة | اختبارات Staging الفعلية وصحة B4 غير مكتملة |
| G37 الرواتب | الجداول موجودة | دالتا `hr_payroll_attendance_is_stale(uuid)` و`hr_payroll_employer_cost(...)` غير مثبتتين بالتوقيع المطلوب، إضافةً إلى دالة الترحيل |
| G38/G41/G42/G43 | معظم مكونات التأسيس موجودة | دوال ترحيل الإهلاك والبنوك والمشاريع والأسطول غير مثبتة |
| G40 الموردون | متطلبات المصدر ظاهرة | دالة صرف الموردين غير مثبتة |
| G62/G63 الموافقات | الوظائف الأساسية مثبتة | لا يكفي ذلك لتجاوز Gate64 |
| G64 | يعتمد على G63 ودوال G35/G36/G39/G40/G41/G42/G43 | تفتقد البيئة أربع دوال ترحيل لازمة، إضافة إلى حارس الاعتماد ودالة إنهاء الترحيل |
| G65 المخزون | الجداول الأساسية موجودة | حارس Gate64 وTrigger الموافقات ودالة المخزون غير مثبتة |
| G67 التأجير | SQL قديم يعتمد جداول `re_*` | ستة متطلبات مفقودة ومراجعة معمارية لازمة قبل محاولة التثبيت |
| G58 القيود اليدوية | دالة الترحيل موجودة | نوع المصدر `manual_journal` غير مسموح به حاليًا في CHECK |
| **G66 الصيانة القديم** | البنية SaaS موجودة (`onexa_tenants`) | **حظر متعمد للتثبيت:** الحزمة نفسها ترفض بنية SaaS |

هذه **حالة فحص كتالوج** وليست أدلة نجاح معاملات مالية، وليست تفويضًا بتطبيق SQL على قاعدة الشركة.

## سلسلة التبعيات الإلزامية

مخطط التثبيت المخزَّن: `docs/runbooks/onexa-b4-install-dependency-manifest.json`.

| موجة | الحزم / الوحدات التي تُراجع معًا | الشرط قبل الانتقال |
|---|---|---|
| 0 | B4 ووظائف الأستاذ والتوازن والإذن | ترحيلات معتمدة مسبقًا على Staging مُستعادة ومختبرة |
| 1 | G35 المبيعات، G37 الرواتب، G38 الإهلاك، G41 البنوك، G42 المشاريع، G43 الأسطول، G58 اليدوي، G62 سياسة الموافقات | مراجعة مخطط كل وحدة، حقوق الوصول، الحسابات، الترحيل وعكسه. لا يلزم إعادة تثبيت الموجود دون سبب |
| 2 | G36 المشتريات، G39 القبض، G63 تشغيل الموافقات | G36/G39 يحتاجان تأسيس G35؛ G63 يحتاج G62 |
| 3 | G40 صرف الموردين | متطلبات G36 وسجل ترحيل المشتريات |
| 4 | G64 ربط الموافقات بالترحيل | **ممنوع قبل تثبيت دوال** G35/G36/G39/G40/G41/G42/G43 وG63. الحزمة تعدل مصادر الدوال السابقة وتحتاج مراجعة فروقها الفعلية في Staging |
| 5 | G65 مخزون التوريد والصرف، ومراجعة توافق G67 التأجير | Gate64/Trigger صالحان، مع استقلال فحص مؤثرات المخزون؛ G67 **ليست ضمن مسار ترقية تلقائي** بسبب اعتمادها على `re_*` |
| مستبعد | G66 كاتب تكلفة الصيانة القديم | لا يجوز تثبيته على SaaS. الإسناد الحديث G73/G74 **قراءة فقط**؛ تُرحَّل التكلفة المسموح بها عبر G42 بحسب المصدر المُعتمد، دون تكرار القيد |

ترتيب الموجات **مصفوفة تبعيات** وليس برنامج SQL قابلًا للتنفيذ؛ قد توجد حزم مثبتة بالفعل، وقد تظهر شروط بنيوية أو تاريخية إضافية لدى الاستعادة المستقلة.

## منع الترحيل المزدوج للصيانة

- أضيف حاجز صريح في `src/lib/runtime-flags.ts`: الثابت `ONEXA_LEGACY_MAINTENANCE_COST_WRITER_ALLOWED = false` يمنع تفعيل كاتب G66 حتى عند تعيين متغير بيئته إلى `true`.
- لا تُعد G74 بديلًا جديدًا يُنشئ قيدًا؛ وظيفة إسنادها **القراءة فقط** للتكاليف المُرحلة سابقًا. يجب تحديد مصدر الاستحقاق الأصيل وتوثيق عدم تسجيل نفس التكلفة في المشتريات أو الرواتب أو المخزون والمشاريع.
- بوابة اعتماد الوحدات في `onexa-b4-module-evidence-gate.mjs` تصنف **13 مسار ترحيل قابلًا للتأهيل + مسار G66 متقاعد عن SaaS**. لا تُقبل حالة تقاعده إلا مع إثبات عدم تثبيته، وإثبات المصدر المحاسبي G42، وإسناد G74، ومطابقة سجل التكاليف، وعزل المستأجر، واعتماد الإدارة المالية والأمن.
- كل الموافقات في نموذج `onexa-b4-module-uat-attestation.example.json` تبدأ `false`؛ نجاح اختبار الأداة ببيانات وهمية لا يعد توقيعًا ماليًا.

## خطوات التنفيذ المسموح بها في Staging بعد الاعتماد

1. استعادة نسخة مستقلة موثقة من القاعدة، وفحص الاختلافات التاريخية، وصلاحيات B2/B3 وG62/G63، وخريطة الحسابات الخاصة بكل شركة.
2. تشغيل فحوص **الكتالوج فقط**:
   `supabase/manual-packages/onexa_b4_release_catalog_READ_ONLY.sql`،
   `onexa_b4_module_publishers_READ_ONLY.sql`،
   `onexa_b4_module_dependencies_READ_ONLY.sql`.
3. مراجعة كل متطلب مفقود في سجل التبعيات؛ لا يجوز تجاوز سبب المنع بإضافة دالة شكلية أو تعطيل `CHECK` أو `Trigger`.
4. مراجعة واعتماد حزم B4 المترابطة، ثم تحضير الوحدات حسب الموجات. اختبار G64 يكون **بعد** تثبيت دوال الموجات السابقة، على نسخة مستقلة، لأنه يعدل شيفرة دوال SQL مباشرة.
5. مراجعة هل G67 القديم متوافق أصلًا مع جداول العقارات الحالية؛ عند عدم التوافق يُصمم مسار SaaS أصيل، ولا تُنقل الجداول القديمة دون مراجعة العزل والعقود.
6. عدم تثبيت G66 مطلقًا على SaaS؛ إثبات تقاعده وإسناد G42/G74 دون ازدواج.
7. تكرار الاختبارات المحاسبية الحقيقية والاعتمادات: المصدر والمراجعة والعملة ودقة الهللة، الثنائيات الأصلية والعكسية، الفترات المغلقة، صلاحيات المعتمد، ربط المشروع/الأصل/المخزون، ورفض الترحيل المتزامن المكرر.
8. يظل **نشر الإنتاج وتفعيل flags محظورًا** حتى تطابق 11 شرطًا عامًا، و17 اختبار اتساق، وأدلة الوحدات، والاستعادة والتراجع وخطة الموافقة الأمنية والمالية المعتمدة.

## أدلة الاختبار الآلية

الفحوص الجديدة:
- `scripts/check-onexa-b4-dependency-plan.mjs`: مقارنة عقد المصفوفة ومتطلبات SQL الفعلية؛ فحص كتالوج القراءة فقط وفرض الحاجز الثابت.
- `scripts/test-onexa-b4-dependency-plan.mjs`: إدخال تبعيات معكوسة ودورات وتغيير حزم ومحاولة تمكين G66 للتأكد من الرفض.
- `scripts/sql-fixtures/onexa-b4-module-dependency-catalog-smoke.sh`: تنفيذ الاستعلام نفسه على PostgreSQL المؤقت قبل وبعد ترحيل سماح `manual_journal` المقترح؛ من دون مستندات عملاء.
- `scripts/test-onexa-b4-module-evidence-gate.mjs`: التأكد من أن وجود كاتب G66 المحظور، أو غياب أدلة عدم ازدواج التكاليف، يمنع قبول النشر.

**الحدود:** لا تُثبت اختبارات المصادر أو وجود الدوال أن الحسابات أو الأرصدة صحيحة. لا توجد ترحيلات أو إصلاحات إنتاجية في هذا التحديث.
